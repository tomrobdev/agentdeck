Archive and delete repos

A repo can't be removed: there is no command, route or button, and its tasks stay in every list. Add archiving, which hides a repo and everything of it and stops its work but can be undone, and deleting, which removes an archived repo and all that belongs to it for good. Written 2026-10-25, after the demo repo kept proposing tasks nobody wanted.

Decisions

  • Two steps: archive first, then delete. Only an archived repo can be deleted, so a misclick never loses history.
  • Archiving is a column, repos.archived_at, not a task status. An archived repo's tasks keep their statuses and come back as they were when it is unarchived.
  • Archiving refuses while one of the repo's tasks is running or cancel_requested; the error says to cancel or wait. Queued tasks just stop being claimed.
  • Deleting is local only. It removes the repo's rows, its tasks' worktrees and local agentdeck/task-* branches, its run and planner logs, settings files and goals file. It never touches GitHub (open PRs stay open), the remote, or the repo's own folder.
  • The rows go in one transaction, children first: task_events, task_plans, runs, notifications of its tasks, tasks, planner_runs, repo.

Archive and unarchive

Migration step at the end of db/schema.ts: repos.archived_at TEXT (null when active). Repo in domain/repo/ and app/src/api.ts get it. In db/: listRepos leaves archived repos out unless asked ({ archived: true }); the task list, summaries, status counts, the review count, claimNextTask, open-PR polling and the planner's due check leave out tasks and repos that are archived (join on repos.archived_at IS NULL). application/repos.ts: archiveRepo and unarchiveRepo, archive refusing while a task of the repo is running or cancel_requested. API: POST /api/repos/:id/archive and /unarchive, and GET /api/repos?archived=1. CLI: agentdeck repo archive <repo>, repo unarchive <repo>, and repo ls --archived; help text in cli/help.ts.

  • pnpm check passes.
  • Tests: an archived repo's queued task is never claimed; its tasks are missing from the list, counts and need-you numbers; the planner skips it; archiving refuses with a running task; unarchive brings the tasks back with their statuses unchanged.
  • No shipped migration step is edited.

Delete an archived repo

application/repos.ts: deleteRepo, refusing unless the repo is archived. It removes each task's worktree and local branch through the git adapter (a missing one is fine), deletes the rows in one transaction in db/ (a new deleteRepo in db/repos.ts, children first, see Decisions), then removes the run logs, settings files, planner logs and the goals file. Files are removed after the rows, so a failure leaves files behind, never rows pointing at missing files; it reports what it couldn't remove. API: DELETE /api/repos/:id. CLI: agentdeck repo delete <repo>, which prints what will go (task, run and worktree counts) and asks unless --yes.

  • pnpm check passes.
  • Tests: delete refuses an active repo; deleting an archived repo with tasks, runs, events, plans and a worktree leaves no rows for it and no worktree; another repo's rows are untouched; a missing worktree or log doesn't stop it.
  • No GitHub or remote command is run (the github adapter is not called).

Archive and delete in the dashboard

ReposPanel.vue: an Archive button on a repo's edit view, and an "Archived" section at the bottom listing archived repos with Unarchive and Delete. Delete opens a confirm that names the repo and the counts that will go and needs the repo's name typed to enable it. The queue's repo filter and the new-task form list active repos only. app/src/api.ts gets the three calls.

  • pnpm check passes.
  • Archiving from the panel removes the repo's tasks from the queue on the next poll, with no reload.
  • Delete stays disabled until the typed name matches.

Not in this plan

  • Closing a deleted repo's open PRs on GitHub.
  • Pausing a repo by hand (today only repo doctor pauses one).
  • Exporting a repo's history before deleting it.
