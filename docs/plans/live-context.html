Live queue state in every Claude session

A Claude session that delegates to AgentDeck reasons from the queue as it last looked, and tasks move underneath it: on 2026-11-01 it proposed waiting on tasks that had already merged. Add agentdeck context, which prints the live state in a few lines, and a hook mode that Claude Code runs on every message, printing what changed since the session's last message. The session then always starts its turn from live state, without having to remember to check. Written 2026-11-01.

Where it starts

  • task_events is a complete, ordered log: every status change, plus PR opened, merged and closed, syncs and merges, each with an increasing id. "What changed since event N" is one query.
  • Workers run with AGENTDECK_TASK_ID set (application/run/claude-run.ts) and the planner with AGENTDECK_PLANNER=1 (application/planner.ts), so a hook can tell them apart from a person's session.
  • The CLI reads the database in its own process, so it works while the daemon restarts. agentdeck status takes about 0.13 s.
  • Claude Code runs SessionStart and UserPromptSubmit hooks with a JSON object on stdin (session_id, cwd, hook_event_name); what the hook prints on stdout is added to the session's context.

Decisions

Decision Why
A CLI command, not a shell script around agentdeck ls, and not an MCP server. The output is written for an agent (a header, then only what changed) and is tested like the rest. An MCP server would still have to be called, which is the step that gets skipped.
The hook's cursor (the last event id the session was shown) lives in a file per session under ~/.agentdeck/hooks/, written by the CLI's hook mode. The use case takes the cursor as input and returns the next one. The database stays free of Claude-session state, and the use case stays a pure read. Files older than 7 days are removed.
Scoped to the repo the session's cwd is in (the registered repo whose path is that directory or above it). Outside a registered repo the hook prints nothing. A session in one repo doesn't need another repo's queue, and the hook can be installed for every repo at no cost.
Never in the way: the hook always exits 0, prints nothing for workers and the planner, and reads only the local database and git (no git fetch). It runs before every message. The daemon already records PR merges, so the database is current without the network.
On SessionStart (start, resume, after compaction): the header and every open task. On UserPromptSubmit: the header, and the changes and open tasks only when something changed. A quiet turn costs one line; compaction loses context, so the full picture comes back then.

The digest, in the domain

domain/task/digest.ts, pure: describeEvent words one task_events row ("started", "done", "PR opened", "merged", "requeued (reason)", "blocked: reason", …) in the domain language; digest takes the header facts, the events since the cursor and the open tasks, groups events by task in order, and returns lines, at most 12 below the header, with "+N more: agentdeck ls" when cut. Reasons are cut to one line of about 80 characters.

  • Unit tests cover every event type, grouping, the line cap and the quiet case (no changes: the header alone).

Reading it

db/tasks.ts: eventsAfter(afterId, repoId, limit) (with each task's title) and lastEventId(), in Drizzle. adapters/git.ts: headSummary(path), the branch, short commit and subject of a checkout. application/task/context.ts: liveContext(db, { repo, after, full }) returns the lines and the next cursor, and repoForPath(db, dir) finds the registered repo a directory is in. Both re-exported from actions.ts.

  • A test with a fixture database: events after a cursor come back in order, scoped to one repo, and the cursor advances.
  • repoForPath finds a repo from a subdirectory, and nothing for an unregistered directory.

The command and its hook mode

cli/agent-context.ts (cli/context.ts already holds the command context): agentdeck context [--repo r] [--since n] prints the full picture (the current directory's repo by default). agentdeck context --hook reads the hook JSON from stdin, does nothing when AGENTDECK_TASK_ID or AGENTDECK_PLANNER is set or the directory isn't a registered repo, keeps the cursor in ~/.agentdeck/hooks/<session_id>.json, and never exits non-zero. Listed in help.ts.

  • A test runs the hook twice for one session against a temporary AGENTDECK_HOME: the second run prints only the header when nothing changed, and the change after an event is added.
  • With AGENTDECK_TASK_ID set it prints nothing and exits 0.
  • pnpm check passes.

Install the hook

.claude/settings.json runs [ -z "$AGENTDECK_TASK_ID$AGENTDECK_PLANNER" ] && command -v agentdeck >/dev/null && agentdeck context --hook || true on SessionStart and UserPromptSubmit, with a 5-second timeout. The delegate skill says the live state arrives with every message, and to run agentdeck ls again before naming a task's state when it might have moved since.

  • A new session in this repo starts with the live state in its context.
  • A worker run shows no hook output in its log.

Not in this plan

  • Installing the hook for every repo (user settings or a Claude Code plugin with the delegate skill).
  • An MCP server for AgentDeck.
  • Warning when agentdeck add --after names a task that is already done and merged.
