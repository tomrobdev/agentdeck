Daemon architecture cleanup

An audit of daemon/src found the layers sound (no I/O in domain/, no SQL outside db/, adapters never import upward) but found three process-model bugs, logic in the wrong layer and code repeated across use cases. Make the daemon the only process that starts claude, then pull the repeated run and gate code into one place each, split the HTTP API into a router and route files, move the daemon's startup wiring out of the CLI, and let the dashboard import the API's types instead of copying them. No behaviour changes beyond step 1. Written 2026-10-25; starts after #44 (the fewer-blocks plan), which touches the same files.

Decisions

Decision Why
Only the daemon starts claude. The CLI's resolve and repo plan call the daemon's API, and fail with a clear message when it isn't running. One owner for every run keeps crash recovery, reload and slot counting correct without a process-owner column. Chosen over recording each run's owning process.
Use cases validate their own input; the API passes bodies through. A wrong type is an ActionError (400). The CLI and the API share the use cases, so validating there covers both. editTask already works this way.
Leave the merged Db object as it is. The Drizzle migration (docs/plans/drizzle.html) reshapes the stores anyway.

Only the daemon starts claude, and it counts every run

Scheduler gets track(p: Promise<unknown>, kind: 'resolve' | 'plan'): a resolve joins running (as resolveConflicts already does), a plan counts as planning, and either one calls tick() when it settles. startApi takes the scheduler, and the resolve and plan routes track their promise. restartWait's callers also count unfinished resolve runs (a new db.countRunningResolves(): runs with kind = 'resolve' and ended_at IS NULL).

New cli/daemon-client.ts: callDaemon(method, path, body?) to 127.0.0.1:API_PORT through node:http, not fetch, whose 300 s headers timeout would cut off a long resolve. Connection refused → die('the daemon is not running; start it with `agentdeck service start`'). An error body → die(error). agentdeck resolve and agentdeck repo plan use it and print what they print today.

isSyncing(id) also returns true when the task has an unfinished resolve run in the db, so the CLI's retry sees the daemon's resolves.

  • pnpm check passes.
  • Tests: a tracked resolve keeps reloadDecision from exiting until it settles; a tracked plan does the same; restartWait names a running resolve; retryTask refuses while an unfinished resolve run is in the db.
  • Test: callDaemon against a stopped port dies with the "not running" message.
  • No code under cli/ imports resolveTask or planNow (grep), so claude runs only start from the daemon process.

One claude-run module and one start gate

domain/run/run.ts: a pure classifyRun(run: ClaudeRun) → { kind: 'cancelled' } | { kind: 'rate_limited'; until; reason } | { kind: 'failed'; reason } | { kind: 'finished'; result }, built from the cancelled / rate-limited / failed branches after runClaude returns in worker.ts and resolveConflicts in conflicts.ts. Keep the environment-block handling #42 added in worker.ts with the caller.

New application/claude-run.ts: startTaskRun(db, task, { kind, worktree, prompt, repo }) opens the log, calls startRun, writes the run settings, calls runClaude with the cancel/pid/usage callbacks, records rate_limited_until and returns the classification, the run id, the log stream and the result fields. The caller still decides what the outcome means and calls finishRun. worker.ts and conflicts.ts use it. planner.ts shares only the usage and rate-limit wiring (a small exported helper), since its run row is a planner run.

New application/gate.ts: startGate(db) → { paused, rate_limited_until, governor: Decision }, read once. Scheduler.gate, canStartResolve, queueState (queue.ts) and status (settings.ts) use it instead of calling decide(…) and reading the setting themselves. The scheduler keeps its own "announce a hold once" logic.

  • pnpm check passes with no test changed except new ones.
  • decide( is called in one place under application/; runClaude( in two (claude-run and planner).
  • Tests for classifyRun: cancel wins over rate limit; a 429 with no reset time is rate limited; no result is failed with the stderr tail.

Typed settings, shared lookups, doctor's I/O in adapters

db/settings.ts: one SETTING_DEFAULTS table and typed accessors for the keys read outside it today: rateLimitedUntil() / setRateLimitedUntil(), setPaused(), reloadOnChange(), notifySettings(), plannerSettings(), prCheckRequested(). Callers in application/ stop using string keys; getSetting/setSetting stay for updateSettings. restart.ts's own setPause goes.

Replace the repeated lookups. domain/task/task.ts: leftoversMessage(task) for the three copies of the "uncommitted work" commit message. domain/run/run.ts: pickRun(runs, { attempt?, run? }) for api/log-stream.ts and agentdeck log.

doctor.ts: ghAuth moves to adapters/github.ts, findClaude to adapters/claude.ts, the temp-dir helper to adapters/git.ts beside addDetachedWorktree, and the raw git worktree prune becomes pruneWorktrees. doctor.ts then imports no node: module.

Split the HTTP API: router, route files, task views

api/http.ts: the generic part, send, readBody (capped at 2 MB, a 413 above it; a parse error throws a BadRequest instead of relying on any SyntaxError), query parsing, CORS and the dispatch loop with its error mapping. api/routes/{daemon,settings,repos,tasks,files,plans}.ts each export routes(ctx): Route[]. api/server.ts keeps startApi({ db, port, scheduler, daemon }), an options object, and composes them. Paths, methods and response shapes stay exactly as they are.

New application/task-views.ts: taskDetail(db, id) and taskViews(db, filter), the repo name, waiting, unblocks, plan_unfinished and hold that server.ts builds inline today. actions.ts re-exports it; agentdeck ls, show and fmtTask use it instead of calling waitingFor/unblocksOf themselves. After this, api/ and cli/ import from application/ only through actions.ts.

Validation: the use cases behind POST routes check the type of each field they read and throw ActionError, as editTask does (addRepo, updateRepo, updateSettings, mergeTask at least). Share the small checkers (text, whole, flag, list) in application/input.ts.

  • pnpm check passes; test/api.test.ts and test/files-api.test.ts pass unchanged.
  • Test: every POST route given a body with wrong-typed fields answers 400, never 500.
  • Test: a body over 2 MB answers 413; malformed JSON answers 400.
  • No file under api/ or cli/ imports application/dependencies.ts or application/queue.ts (grep).

Move the daemon's wiring out of the CLI

New src/daemon.ts: runDaemon({ db, once }), everything runScheduler in cli/daemon.ts does today (checkout commit, source watcher, reload decision, signal handlers, the API, the scheduler). It reports through a log callback and returns or throws; the CLI command prints and calls die. The EADDRINUSE message stays. src/cli.ts stays where it is.

agentdeck clean's body becomes removeTaskWorktree(db, id) in application/tasks.ts, with POST /api/tasks/:id/clean. The agentdeck set key-to-patch mapping becomes settingPatch(key, value) in application/settings.ts. Update the Boundaries section of CLAUDE.md to name src/daemon.ts as the daemon's composition root.

  • pnpm check passes, including pnpm test:crash.
  • cli/daemon.ts imports no adapter except service.ts.
  • Tried from the task's worktree on a separate home and port (AGENTDECK_HOME=$(mktemp -d) AGENTDECK_PORT=4318 node daemon/src/cli.ts daemon): it starts, answers /api/status, and stops on Ctrl-C.

The dashboard imports the API's types

New daemon/src/api/contract.ts: the request and response types of every route, declared there or re-exported from domain/, and importing nothing else (no db/, application/ or node:). A daemon/src/api/contract-check.ts, like db/types-check.ts, asserts that each use case's return type is assignable to its contract type, so pnpm typecheck fails on drift.

app/src/api.ts splits into types.ts (import type … from '../../daemon/src/api/contract.ts', plus dashboard-only types), client.ts (call and api) and format.ts (when, relTime, ago, describeState, …). Keep api.ts as a re-export so the components' imports don't change in this step. If the app's stricter flags (noUnusedLocals) trip on imported domain/ files, declare those types in contract.ts instead of re-exporting them. Remove the "keep them in sync" rule from CLAUDE.md.

  • pnpm check passes, including the app's vue-tsc.
  • app/src declares no interface that contract.ts already exports (grep the old names).
  • Changing a field's type in a domain type makes pnpm typecheck fail in the app.
