A run a restart ended continues its claude session

A daemon restart (SIGTERM from agentdeck restart --now, service stop or launchd, or a crash) kills the running task's claude. recoverOrphans ends the run as failed with "daemon restarted" and requeues the task, and the next run starts the work over, because no run passes --resume and session_id is only stored when a run ends. On 2026-11-01, #72 and #87 each lost a run this way. Store the session as soon as claude names it, mark a run a restart ended as interrupted, and have the task's next run resume that session with a short prompt, falling back to a fresh run when the session is gone. Written 2026-11-01.

Decisions

Decision Why
A run a restart ended gets the outcome interrupted, not a flag beside failed. The run did not fail. Every reader of outcome (the next run's prompt, the PR body's run table, the first-run measure in agentdeck stats, the dashboard, agentdeck show) would go on calling it a failure with a flag, and each would need to learn the flag. outcome is free text, so a new value needs no migration; a flag would need a column. result_text stays "daemon restarted".
claude's system/init line reaches the application through a new onSession callback on runClaude, which stores it with db.setRunSession. The session id a run ends with falls back to the init's when there is no result, so a failed run no longer clears it. The same shape as onUsage and onSpawn: adapters never import db/.
Whether to resume is resumableSession(task, runs) in domain/run/run.ts: the latest work runs, back to the first that was not interrupted, of the attempt the task is on; the newest of them that recorded a session. A restart gives the attempt back (recover already does), so the next run is the same attempt and continues the same session. A person's retry after a restart-failed or cancelled task starts a new attempt, and so a fresh session. Looking past an interrupted run that never reached claude (a second restart during setup) keeps the session.
A resume that fails at once (no result and no init line, or "No conversation found") is followed by a fresh claude in the same run row, with the normal prompt; the log records agentdeck_resume_failed. The resume never started a session, so nothing was attempted; a second row would share the attempt and the log file, be counted as a run by the crash test and agentdeck stats, and be picked by pickRun for the attempt.
The resume prompt is short and the arguments are otherwise those of a fresh run: same --settings, tool rules, --append-system-prompt, model and turn limit, plus --resume <session>. The session already holds the task's prompt and plan. The worker still syncs before the run, so the prompt says that what was left uncommitted may now be a commit of AgentDeck's and that the base branch may have been merged in.

Store the session id when claude names it

runClaude reads session_id off the system/init line, keeps it on ClaudeRun.sessionId and calls onSession. startTaskRun stores it with db.setRunSession. resultFields takes the init's id when the result has none.

  • A test shows a running task's run has its session id while ended_at is still null.

Mark a run a restart ended as interrupted

recoverOrphans sets outcome = 'interrupted' (INTERRUPTED in domain/run/run.ts) on unfinished task runs; planner runs stay failed. The first-run measure leaves interrupted runs out. The dashboard gives the outcome a colour (.s-interrupted). A fresh run after an interrupted one says so in its prompt instead of "the previous attempt ended as failed". The crash test tells real runs by the outcome.

  • After recoverOrphans the run's outcome is interrupted and its result text "daemon restarted".

Resume the interrupted session

resumableSession and buildResumePrompt in the domain; claudeArgs takes an optional session and adds --resume; the worker asks for the session and hands startTaskRun both prompts.

  • A test restarts a daemon (SIGTERM) mid-run; the next run's arguments hold --resume <id>, and the task's attempts and the run's attempt number are unchanged.
  • Unit tests cover resumableSession (same attempt only, looks past interrupted runs without a session).

Fall back to a fresh run when the session is gone

resumeFailed(run) in the domain; startTaskRun starts a fresh claude with the normal prompt when it is true. The fake claude keeps the sessions it started and answers --resume of any other the way claude answers a missing session ("No conversation found" on stderr, exit 1, no output).

  • A test: a resume of a missing session ends in a fresh run on the same branch that finishes the task, in one run row.

Repeated restarts still fail the task

restarts and MAX_RESTARTS are untouched: each recovery still counts.

  • A test: a task whose resumed runs keep being interrupted fails at MAX_RESTARTS.

Docs and checks

docs/architecture.md says what a restart does to a run. In the worker's sandbox ps is refused, so the existing reapOrphans test (it reads a process's start time with ps) fails there and only there.

  • pnpm check:fast passes.
  • node daemon/scripts/crash-test.mjs 10 passes, and its logs show runs resuming after the SIGKILL.
