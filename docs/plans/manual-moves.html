Mark tasks done by hand

A blocked or failed task can only be retried or cancelled, even when a person finished or landed the work themselves. Add a mark_done event a person triggers (board drop, task page, CLI), have tasks marked done by hand release the tasks waiting on them, and fix the PR refresh, which never looks at blocked tasks, so a PR merged on GitHub leaves its task blocked forever. Every move stays a named lifecycle event through applyEvent. Written 2026-10-25.

Decisions

Decision Why
Manual moves are named events in RULES, never a status picker. This plan adds one a person triggers, mark_done (blocked or failed → done), and one the daemon triggers, pr_merged (blocked or failed → done when the task's open PR turns out merged). A raw status write can leave a task in a state nothing expects (running with no process). Named events keep the guarded UPDATE … WHERE status IN (…) and the timeline.
A migration step adds tasks.done_by TEXT: 'person' when mark_done set the status, null otherwise, cleared whenever the task leaves done. A dependency is met when its task is done and either its PR is merged, or it has no PR and its repo has pr_mode off (as today), or done_by = 'person' and its PR is not open. A person-done task with an open PR still holds its dependents until the merge. Without it, a person-done task in a repo that opens PRs leaves its dependents waiting forever. Recording who said done is explicit, unlike setting pr_state = 'merged' for a merge that didn't happen.
mark_done uses no attempt, clears blocked_reason and needs, and sends no notification. A person did it; the timeline records it with their optional note.

The mark_done and pr_merged events, and done_by

domain/task/lifecycle.ts: TaskEvent gains { type: 'mark_done' } and { type: 'pr_merged' }; RULES maps both from blocked and failed to done; TRANSITIONS lists blocked → done and failed → done. db/tasks.ts applyEvent: both clear blocked_reason and needs; mark_done sets done_by = 'person'; any move out of done sets it to null. Append a migration step for done_by, mirrored in db/tables.ts, Task and api/contract.ts.

Dependencies: the rule in the Decisions table, in both domain/task/dependency.ts and DEPENDENCY_MET in db/tasks.ts. Add a test that runs the same cases through both (a dependency per status, pr_state, pr_mode and done_by) and checks that they agree.

application/tasks.ts: markDone(db, id, note?), an ActionError naming the status when the event is refused (done releases dependents, so no warnStuckDependents). API: POST /api/tasks/:id/done with an optional { note }, answering the task detail and waking the scheduler. CLI: agentdeck done <id> [--note "…"], in help.ts too.

  • pnpm check passes, including pnpm db:check.
  • Lifecycle tests: mark_done moves blocked and failed to done and is refused from every other status; attempts are unchanged; done_by is set, and cleared by a retry.
  • Dependency tests: a task after a person-done task with no PR starts; after a person-done task with an open PR it waits; the SQL and the domain rule agree on every case.

Refresh the PRs of blocked and failed tasks

openPrTasks also returns blocked and failed tasks with pr_state = 'open' (a conflict blocks a done task and keeps its PR open; a retry that fails keeps it too). In refreshPrStates, a merged PR on such a task updates pr_state and applies pr_merged, logged like other state changes; a closed one only updates pr_state. Mergeability and conflict resolution stay for done tasks only.

  • pnpm check passes.
  • Tests with the fake github: a blocked task whose PR is merged becomes done with pr_state merged and a pr_merged timeline entry; a closed one stays blocked with pr_state closed; a blocked task is never sent to resolveConflicting.

Mark done from the board and the task page

app/src/taskView.ts: BoardMove gains mark_done; boardMove returns it for a blocked or failed task dropped on the Done column ("Drop to mark done"). The drop asks for confirmation, naming the task, and when it has an open PR says its dependents wait for the merge. The task page of a blocked or failed task gets a "Mark done" action beside Retry, with an optional note. client.ts: markDone(id, note?). Timeline labels in OverviewTab.vue: mark_done "marked done by hand" (plus the note), pr_merged "PR merged on GitHub".

  • pnpm check passes, including the app's vue-tsc.
  • boardMove tests: blocked and failed to Done give mark_done; queued, proposed, cancelled and stuck-queued tasks to Done give nothing. The app has no test runner: put the test in daemon/test/ importing app/src/taskView.ts (as themes.test.ts reads app files), or, if the daemon's typecheck rejects that import, move the move rule into a dependency-free module both can import.
  • A merged or person-done task shows its timeline entry with the right label.

Not in this plan

  • Other manual moves considered and left out: queued → proposed (park), cancelled → proposed or done, closing a PR and cancelling in one move (withdraw), a reason on cancel.
  • Merging from the board by dropping on Merged: that stays the merge dialog.
