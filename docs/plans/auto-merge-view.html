See whether a task will auto-merge

Whether a task's PR will merge on its own is worked out on every PR refresh and then thrown away unless the answer is "merge", so the list shows nothing and the task page only shows the setting. Keep the latest answer on the task, and show it, with its reasons, in the CLI's ls and show and the dashboard's list, board and task page. Before a PR exists, say whether auto-merge is on, which limits will apply and, on the task page, how the branch measures against them now. Written 2026-11-01.

Where it starts

  • autoMergeOn(task, repo) (domain/pull-request/auto-merge.ts) says whether auto-merge is on: the task's own setting, else the repo's, except a planner proposal the repo auto-approves.
  • autoMergeCheck gives { verdict: 'merge' | 'wait' | 'never', reasons } from the PR's details, the last tested run and the repo's limits (auto_merge_max_lines, auto_merge_skip).
  • The PR refresh (refreshPrs, application/pull-request/pull-requests.ts) runs the check for every open PR of a done task with auto-merge on, keeps the merge ones and drops the rest. The merge dialog runs it again live, from GitHub.
  • The task page's sidebar has the auto-merge select (on, off, repo's setting). agentdeck ls, agentdeck show and the dashboard's list and board say nothing about auto-merge.

Decisions

Decision Why
The refresh stores its latest check on the task (verdict, reasons, when). Views read it; they never ask GitHub. The CLI runs in its own process, so the database is the only place the daemon's answer can be shared. Lists stay fast and work offline.
One pure function in the domain turns the setting, the stored check and the repo's limits into what every view shows: a state, a short label, the reasons and where the setting comes from. The CLI and the dashboard word it the same way, and the dashboard's lib/ doesn't copy the rules.
The task page (and agentdeck show) of a task with a branch and no open PR measures the branch against the limits locally: lines changed against the base and paths under a skipped prefix. Lists don't. It answers "will this merge on its own?" while the task still runs, from git alone. One task at a time keeps the cost to one git diff --numstat.

The states

State When Label
off Auto-merge is off for the task auto-merge off
on On, and no PR checked yet auto-merge on
merge On, and the last check said merge will auto-merge
wait On, and the last check said wait auto-merge waiting: first reason
never On, and the last check said it needs a person needs a person to merge: first reason

Keep the latest check

A new migration step adds tasks.auto_merge_check (JSON { verdict, reasons }, NULL when none) and tasks.auto_merge_checked_at; db/tables.ts, the Task type and migrations.lock follow. refreshPrs writes every check it runs, not only merge, guarded on the task being done with its PR open. The check is cleared when the PR is merged or closed, and when auto-merge is turned off for the task (setAutoMerge).

  • A test: a refresh that finds a PR over the line limit stores never with that reason, and merging clears it.
  • Turning auto-merge off for a task clears its stored check.
  • pnpm check passes.

One view of it, from the domain

autoMergeView(task, repo, measured?) in domain/pull-request/auto-merge.ts returns { state, label, reasons, source: 'task' | 'repo' | 'planner', checked_at, limits: { max_lines, skip, tests } }, with the states and labels above. A stored check counts only while the PR is open; source says where on or off came from (planner: off because the repo auto-approves planner proposals). measured, when given, is the branch's local diff (lines, paths) and adds reasons such as "now 1,240 lines, over the limit of 1,000" or "touches .github/workflows/x.yml". TaskView gets auto_merge; taskDetail also measures the branch when it has no open PR. api/contract.ts follows.

  • Unit tests for each state, each source, and the measured reasons.
  • pnpm typecheck passes, including contract-check.ts.

The CLI

agentdeck ls adds the label to a task's line when the state isn't off, after the PR. agentdeck show prints an auto-merge line (the label and where the setting comes from), then each reason, when it was checked, and the limits that apply. agentdeck context marks open tasks the same way.

  • A task with auto-merge on and a PR over the limit shows "needs a person to merge: … over the limit …" in both.
  • pnpm check passes.

The dashboard

List and board rows get a small auto-merge mark for every state but off, coloured by state, with the label and reasons in its tooltip. The task page's sidebar shows the label and reasons under the auto-merge select, when it was checked, and the limits; for a task with a branch and no open PR, the measured numbers. The words come from the API (label, reasons), not from the app.

  • Each state is visible in the list, the board and the task page, in light and dark themes.
  • pnpm check passes.

Not in this plan

  • Changing what auto-merge decides, or its limits.
  • A filter for "will auto-merge" in the queue (easy to add once the state is on the view).
