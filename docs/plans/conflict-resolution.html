Keep task branches up to date and resolve merge conflicts

Task branches fall behind their base branch while they wait, run or sit in an open PR, and a PR that conflicts cannot be merged. The daemon merges the latest base into the branch before every run and when an open PR starts conflicting, resolves a clean merge by itself, hands real conflicts to a short claude resolve run, and blocks the task with the conflicting files when that fails.

Decisions

  • Merge the base into the branch, never rebase: no force pushes, and squash merging hides the merge commit.
  • The daemon runs git fetch and git merge origin/<base> in the worktree (agents cannot fetch). Without an origin it merges the local base.
  • A resolve run never uses an attempt and is stored as its own kind of run, next to the work runs.
  • Per-repo auto_resolve (on by default) gates conflict runs that start on their own; clean merges always happen. A person asking by hand overrides it.
  • The task timeline records "Brought in main: clean" or "Resolved conflicts in N files" (event type sync).

Domain: decisions and vocabulary

domain/pull-request/conflict.ts: is a PR conflicting, the timeline texts, the blocked reason. domain/run/prompt.ts: the resolve prompt (conflicting files, both sides' commit messages, the task's goal). Run gets a kind (work | resolve). The lifecycle gets a conflict event (done to blocked); history gets the sync type.

Schema and stores

Migration step 9 appended: repos.auto_resolve (default 1) and runs.kind (default work). startRun takes a kind; recordSync writes a timeline row without a status change; applyEvent handles conflict with its reason.

Git adapter

Merge a ref into a worktree and report up to date, merged or conflicts (with the files); abort a merge or reset to the commit before it; finish a merge the agent staged; find conflict markers left behind; list both sides' commit subjects; tell whether the branch is ahead of its remote.

Application: bring in the base

application/conflicts.ts holds the shared step (fetch, merge, tests, resolve run, abort) and syncTask for a done task: clean merge, tests, push; conflicts start a resolve run; on success push and stay done; on failure abort and block through applyEvent with the files as the reason, and notify. An in-flight set stops two syncs, and a retry, from touching one worktree.

At the start of every run

The worker brings the base into the branch after setup and before claude, on retries too. A clean merge or a resolved conflict goes on the timeline and the run continues; an unresolved conflict blocks the task; a rate limit requeues it without using an attempt.

When an open PR becomes conflicting

refreshPrStates also reads mergeability and returns the conflicting tasks; the scheduler resolves them when the governor allows and a slot is free. mergeTask asks for an immediate re-check of the open PRs (a setting the scheduler watches, so it works from the CLI too), repeated briefly while GitHub still reports UNKNOWN.

By hand: API, CLI and the repo setting

POST /api/tasks/:id/resolve, agentdeck resolve <id>, auto_resolve in updateRepo, the CLI's repo set and the log stream (which can now pick a run by id).

Dashboard

app/src/api.ts mirrors the new fields. The merge dialog shows a Resolve conflicts button where the conflict is a blocking problem. Runs are picked by id and a resolve run is labelled as one. The timeline shows the sync events. The repo editor gets an auto-resolve switch.
