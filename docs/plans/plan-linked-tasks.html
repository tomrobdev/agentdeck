Tasks linked to plan steps

A task's prompt says in prose which plan steps to follow, the worker never sees the plan's text, and nothing checks that the steps got done. Give plan steps their own done criteria, let a task name the plan and steps it carries out, put those steps into the worker's prompt, and flag linked steps a run leaves unfinished. Written 2026-10-24. It takes over step 4 of docs/plans/plan-first.html and is the "split a plan's steps into tasks with --after" that plan left out.

Decisions

  • Done criteria are a list: <ul data-plan-done> inside a step, one <li> per check. Each becomes a checkbox in the PR. Optional and additive, so the format stays version 1, and stored plans need no migration (they are parsed when read).
  • The daemon puts the linked steps' text into the worker's prompt, and names the plan's path too. The worker is sure to see the steps and spends no turns finding them.
  • --plan without --steps means every step that isn't done or skipped when a run starts.
  • A linked step a run leaves unfinished is a warning (a task event, a badge, a line in the PR), not a change of outcome. Usually the work is there and only the markup wasn't updated; blocking would waste an attempt. Revisit if it turns out common.
  • A linked task's prompt needs only Goal, Out of scope and Constraints from PROMPT_SECTIONS. The steps supply Change and Definition of done.
  • Plans are committed to the base branch before their tasks are queued, so the daemon can read and check them at add time.

domain/plan/plan.ts: PlanStep gets done: string[]. parsePlan reads the step's first [data-plan-done] element: the text of each <li>, or the element's whole text as one item when it has no list items. Mirror the type in app/src/api.ts. PlanCard.vue shows a step's criteria when the step is expanded. docs/plan-format.md gets a table row and the template a data-plan-done list. The worker system prompt (domain/run/prompt.ts) mentions the element in its plan line.

Put the linked steps in the prompt

Before each run, worker.ts reads the linked plan from the worktree (the branch's copy carries earlier attempts' statuses) and passes its HTML to buildPrompt. A pure function in domain/run/prompt.ts builds a block after the task's prompt: the plan's path, title and summary, then each linked step that isn't finished (its title, status, text and done criteria), and "Do only these steps. Set each one's data-status in <path> as you go, and commit the plan with the work. Mark a step you can't do blocked and say why inside the step." This needs the step's body text, so parsePlan (or a sibling) also returns it. A task with no plan_path but exactly one plan from its branch (a plan-first build) gets the same block for that plan's unfinished steps: that is plan-first.html step 4. If the plan file is missing in the worktree, the prompt says so and the run goes ahead on the task's prompt. Update the delegate skill and PROMPT_SECTIONS: a linked task's prompt has Goal, Out of scope and Constraints only.

  • pnpm check passes.
  • Tests for the block: linked steps by id, every unfinished step when plan_steps is null, finished steps left out, a retry seeing updated statuses, a missing plan.
  • Step 4 of docs/plans/plan-first.html is set to done, with a line pointing here.

Flag unfinished steps, and check them off in the PR

After collectPlans in worker.ts, compare the linked steps with the branch's plan. If the run ended done and any linked step isn't done or skipped, record a task event naming them (a new history event type, with its timeline text in domain/). Don't change the outcome. buildPrBody in domain/pull-request/pr.ts gets a "Plan" section: each linked step's title and status, and its done criteria as a - [ ] checklist for the reviewer. The task page and the list row show a badge when a done task has unfinished linked steps.

  • pnpm check passes.
  • Tests: a done run with all linked steps finished records no event; one with an unfinished step records it and stays done; the PR body lists criteria as checkboxes and leaves out the section when the task has no plan.
  • app/src/api.ts matches any type the badge needs.

How it gets built

Four AgentDeck tasks on the AgentDeck repo, one per step, chained with --after so each starts from the last one's merged code. Each prompt names this plan and its one step. Until step link lands, that link is prose in the prompt.

Not in this plan

  • Checking done criteria by machine. They stay prose for the worker and the reviewer; test_cmd is still the only automated check.
  • The planner proposing plans, or linking its proposals to steps.
  • Splitting a plan into linked tasks with one command.
  • Changing the outcome when linked steps are unfinished (see Decisions).
