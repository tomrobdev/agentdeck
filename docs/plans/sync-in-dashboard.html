Syncs in the dashboard

A sync of a task in review shows in the dashboard while it runs, whoever started it: a dashboard button, agentdeck sync or the daemon's own auto-resolve. Merging a PR that conflicts becomes one flow in the merge dialogs: sync, then merge.

Why

#105 and #98 conflicted with main. They were synced from the CLI, each with a resolve run of a few minutes, and the dashboard showed nothing: both sat in Review saying "auto-merge waiting: the branch has conflicts" until the PR refresh read them again.

  • liveRuns() (db/runs.ts) reads only kind = 'work' runs, and liveView (domain/run/live.ts) returns null unless the task is running. A resolve run belongs to a done task, so TaskSummary.live is null throughout.
  • A clean sync, with no claude, is not visible at all.
  • QueueView.vue keeps its own syncing list, so "Syncing…" shows only in the window whose Sync button started it.
  • isSyncing(db, id) in application/sync.ts already knows both cases: the in-process lock (the daemon serves the API, so it sees its own syncs) and db.hasRunningResolve(id).
  • BulkMergeDialog.vue (Merge all and the bulk merge) lists each PR left open with its reason from mergeAll, but a conflicting one can't be synced from there. MergeDialog.vue has "Sync with base" for one PR.

The sync view on task summaries

Give TaskSummary a sync field for a done task: null when no sync is under way. Otherwise it says when the sync started, whether a resolve run is settling conflicts, and that run's live turns and last tool, worded as LiveView is.

  • Decide its shape in domain/run/live.ts (pure), beside liveView, and add it to api/contract.ts and api/contract-check.ts.
  • Fill it in application/task/task-views.ts from isSyncing and the task's unfinished resolve run. Read the live resolve runs with one query for the whole list, as liveRuns() does for work runs, not one per task.
  • Give each mergeAll skipped entry a conflicting flag, true when the refusal was a conflict with the base branch. Take it from the merge findings' kind (domain/pull-request/merge.ts), not by matching the reason's text.
  • A domain test covers the sync view: none, a clean sync under way, and a resolve run with its turns and tool.
  • A test with a db fixture shows taskViews giving a done task with an unfinished resolve run its sync view.
  • The mergeAll test checks conflicting on a conflicting PR and on one held for another reason.

Show it in the queue and on the task page

  • List rows and board cards of a task in review show its sync from the summary: "Syncing with main…", or "Resolving conflicts" followed by the live part (time, turns, tool) as describeLive words it.
  • Replace QueueView.vue's window-local syncing list with the summary's state. A task with a sync under way keeps Merge, Sync and Merge all disabled for it, and can't be dragged.
  • A row with a resolve run under way opens on the Runs tab, as a running task does (openingTab in lib/taskView.ts).
  • The task page's header says a sync is under way, and Merge waits for it. The resolve run in Runs and Overview shows as live.
  • The change stream (composables/useChangeStream.ts) must refresh the list while a resolve run moves, as it does for a running task's live state. Check this, and fix it if it doesn't.
  • In the dashboard against a daemon, a resolve run started with agentdeck sync <id> shows on that task's row and card without anything clicked in the window, and goes away when the sync ends.
  • QueueView no longer keeps its own list of syncing tasks.

Sync from the merge dialogs

  • In BulkMergeDialog.vue, after the merge, each PR left open because it conflicts (conflicting) gets a Sync button. When there are several, one "Sync the N conflicting" button syncs them one at a time.
  • Each shows syncing, then synced or blocked with syncLine's wording (lib/landing/landing-wording.ts). The ones that synced cleanly can be merged from the same dialog in one go (api.mergeAll).
  • Closing the dialog doesn't stop a sync: the daemon finishes it, and the row shows it from the summary (step queue).
  • In MergeDialog.vue, check that Merge is ready once "Sync with base" comes back clean, and fix it if not.
  • In the dashboard, Merge all over a set that includes a conflicting PR offers Sync for it, then merges it once it synced.
  • pnpm check passes.
